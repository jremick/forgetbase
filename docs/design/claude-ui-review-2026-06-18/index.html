A fresh design pass over the live React UI (apps/web/src/App.tsx) and the saved design package. What's working — keep it

retain
  • Restrained slate + teal-blue palette with severity colors reserved for health/risk. No gradients, no editorial cream/serif. This is the right register for an operational control plane — keep it verbatim.
  • Sensitivity rendered as a keyline + label, visually distinct from status chips. This separation is a genuine product asset; the mockups preserve it exactly.
  • Provenance-forward primitives (trust banner, stable IDs, instruction well) and accessibility scaffolding (skip link, :focus-visible, ARIA roles).
  • Grouped Read / Work / Operate nav with a resizable tree. Good landmarks for three very different audiences.

Top findings

ordered by severity
H1

The Operations route is a 25-section mega-page

In the live app, App.tsx:2708–4240 renders Access, Providers, Policies, Telemetry, Approvals, Exports, users, groups, keys, sessions, evals, and every policy form into one scrolling column. There is no per-domain landing, no task grouping, and the nav routes for those domains effectively resolve into the same surface. Fix: Operations becomes a router-to-work overview; each domain owns a dedicated, shallow page.

H2

Destructive actions fire inline with hardcoded reasons

Approve/deny and restore run immediately; denial reason is hardcoded (App.tsx ~3290) and restore appears both in a toolbar and a confirm. Fix: a single destructive-staging surface — dry-run evidence, required reason, impact preview, typed confirm — and never duplicate the trigger.

H3

No real loading / empty / error / no-access system

Async states are bare "No X loaded." paragraphs; errors are plain red text with no code or next step; reader-vs-admin permission affordances are missing. Fix: a four-state system (skeleton, empty, error, no-access) applied consistently, with conservative no-access disclosure.

M4

Library shows the same content three ways

The saved mockup stacks the left nav tree, an in-page folder browser, and a catalog table — three representations of one library on one screen. main-page-mockups/index.html:190–267 Fix: tree lives only in the left nav; the page is one scannable catalog with a filter bar and a compact summary strip.

M5

Search blends the synthesized answer into the evidence list

Answer draft and citations share the same card styling, flattening hierarchy. Fix: answer is one primary card with grounding/cost/citation-floor chips; evidence is a ranked list below; denied results get an explicit admin rail.

M6

The agent-instruction object renders as a raw blob

Agent instructions are the product, yet they show as <pre> text. Fix: render the schema structurally — kind, target agents, input/output contracts, constraints, failure modes, escalation — so operators can debug what an agent actually consumes.

M7

Policies cram unrelated domains into a 2×2

Managed-query, PII, retention, cache, and action-execution policies sit in one flat grid with inconsistent depth and no saved-vs-current state. Fix: a policy index (sub-nav rail) with a sticky dirty-state save bar per domain.

M8

Heavy 4-up metric tiles repeat on every page

26px metric tiles dominate reader and admin pages alike. Fix: a compact summary strip for at-a-glance counts; reserve large tiles for the Operations overview only.
