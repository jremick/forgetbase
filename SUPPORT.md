# Support

ForgetBase is experimental self-hosted software. Support is best effort until a stable release exists.

## Use GitHub Issues For

- reproducible bugs
- focused feature requests
- documentation gaps
- synthetic demo corpus improvements

Include the version or commit, the surface involved, reproduction steps, environment details, and the checks you ran.

## Do Not Use Public Issues For

- suspected vulnerabilities
- private/customer corpus debugging
- production incident support
- secrets, raw tokens, database dumps, or confidential content
- general troubleshooting without a reproducible path

## Security Reports

Do not open a public issue for a suspected vulnerability.

Use [Report a vulnerability](https://github.com/jremick/forgetbase/security/advisories/new). See [the security policy](SECURITY.md) for the private reporting process and fallback.

## Beta Boundaries

See [Public Beta Compatibility](docs/PUBLIC_BETA_COMPATIBILITY.md) for supported trial paths, volatile surfaces, data expectations, and known unsupported cases.
